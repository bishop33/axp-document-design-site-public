# 한글 A4 기업현황 제작 사양 v1

상태: `proposed` · 2026-09-23 · 편집 디자이너안 v2에 첫 적용 · Bishop 검토 전

## 적용 범위

- 우선 문서: 기업현황. 이후 투자검토 IM → 기술제안서 → 산업분석 순서로 변형한다.
- 매체: A4 세로, 화면 정독 및 PDF 출력. 발표자료 기준과 분리한다.
- 목표: 실적·사업구성·현금·의사결정처럼 역할이 다른 페이지를 하나의 기업 보고서 체계 안에서 읽게 한다.
- 이 사양은 테스트에서 선택된 편집 디자이너안의 밀도와 강조 방식을 유지하기 위한 첫 제안이다. 최종 권장값이나 전 문서 공통 정답이 아니다.

## 1. 문서 계약

제작 시작 전에 다음을 필수 입력으로 받는다.

1. 독자와 사용 상황
2. 독자가 내려야 할 판단
3. 보고 기간과 수치 단위
4. 페이지별 질문·핵심 주장·근거·한계
5. 관측값·계산값·가정·미제공값·작성자 제안의 구분
6. 반드시 유지할 내용과 축약 가능한 내용

입력에 없는 원인·전망·고객별 값·ROI는 생성하지 않는다. 내용 공백은 디자인 요소로 가리지 않고 `미제공` 또는 추가 자료 요청으로 남긴다.

## 2. 문서의 공식 체계

- 모든 페이지에 기업명, 문서명, 섹션명을 같은 위치에 반복한다.
- 첫 페이지에서 보고 기간, 용도, 검토 상태를 명시한다.
- 페이지 번호는 `현재 / 전체`로 통일한다.
- 금액 단위와 기간은 표 제목 또는 열 제목에서 반복 확인할 수 있게 한다.
- 기업명은 예시 원고 안에만 두고 라이브러리의 문서 유형 제목에는 사용하지 않는다.

## 3. 페이지 역할

기업현황 기본 4쪽은 다음 역할을 갖는다. 내용에 따라 페이지는 늘릴 수 있으며 4쪽을 맞추려고 내용을 삭제하지 않는다.

1. 성과 요약: 핵심 지표와 경영 판단
2. 사업 구조: 매출 구성·고객·지속성
3. 재무·현금: 잔액과 기간 흐름, 제약
4. 의사결정: 결론, 근거 공백, 후속 조치

각 페이지는 제목 → 한 문장 요약 → 주된 근거 → 해석 → 조건·한계 순서를 기본으로 한다. 같은 페이지에서 질문이 둘 이상이면 근거 영역을 분리하고 각각의 제목을 붙인다.

## 4. 제목과 줄바꿈

- 제목은 페이지의 결론을 한 문장으로 쓴다. 명사만 나열하거나 설명형 소제목을 확대하지 않는다.
- 제목은 자동 줄바꿈에 맡기지 않고 편집자가 의미 단위를 정한다. 양보·조건과 핵심 판단, 주제와 결과처럼 함께 읽어야 할 구를 한 행으로 묶는다.
- raw `<br>` 대신 의미 행을 나타내는 `.title-line` span을 사용한다. 각 행은 완결 문장이 아니어도 읽는 호흡과 문법 관계가 분명해야 한다.
- 조사가 다음 줄 첫머리에 홀로 남거나, 숫자와 단위가 분리되거나, 수식어와 핵심 명사가 갈라지는 줄바꿈은 허용하지 않는다.
- 예: `기말현금은 20억원이지만` / `연중 가용 수준은 확인되지 않았습니다`처럼 사실의 전제와 판단을 나눈다.
- 제목은 최대 2행을 우선하며 3행이 되면 글자 축소보다 문장 편집과 폭 조정을 먼저 검토한다.
- 제목 뒤 도입문은 제목을 반복하지 않고 기간·수치·판단의 한계를 보충한다.

## 5. 조판 profile

첫 적용값이며 실제 PDF 검수 후 변경한다.

| 항목 | proposed 값 | 변경 규칙 |
|---|---:|---|
| 판형 | A4 세로 210×297mm | 발표용으로 전용하지 않음 |
| 여백 | 상16 / 좌우18 / 하13mm | 표가 넓어도 좌우15mm 미만으로 줄이지 않음 |
| 바탕 grid | 6열, 거터5mm | 내용 관계에 따라 6 / 4+2 / 3+3으로 병합 |
| 본문 | Pretendard 9.5/14pt | 9pt 미만으로 축소하기 전에 페이지·폭·원고 조정 |
| 도입 | 11/17pt | 제목과 같은 내용을 반복하면 원고 수정 |
| 제목 | 22/28pt, 600 | 2행 우선, 의미 단위 행을 명시 |
| 소제목 | 11.5/16pt, 600 | 뒤따르는 내용과 3mm 이내 결속 |
| 표 | 9/13pt | 숫자 오른쪽, 텍스트 왼쪽, 행 역할에 따라 굵기 사용 |
| 주석 | 8.5/12pt | 실제 출력에서 읽히지 않으면 축소 금지 |
| 섹션 사이 | 6mm | 내부 문단 간격보다 반드시 크게 유지 |
| 표 셀 | 상하2.1 / 좌우2mm | 긴 셀은 글자 축소보다 열폭·행 분할 검토 |

Pretendard 400/600을 로컬에서 불러온다. 대체 서체가 사용되면 같은 줄바꿈과 4쪽 출력을 보장하지 않으므로 별도 렌더 검수가 필요하다.

## 6. 강조와 기업 보고서다움

- 기본은 흰 지면, 짙은 본문, 한 가지 식별색이다. 식별색은 섹션 번호·당기 열·핵심 상태에 제한한다.
- 숫자 강조는 크기, 굵기, 열의 옅은 색면 순으로 사용한다. 색만으로 의미를 전달하지 않는다.
- 경고와 한계는 무조건 박스에 넣지 않는다. 왼쪽 규칙선과 짧은 상태명으로 문서 흐름 안에 둔다.
- 페이지마다 같은 모듈을 반복하지 않는다. 성과는 KPI+표, 사업은 차트+해설, 현금은 식+표, 의사결정은 근거표+조치 순서처럼 정보 역할에 따라 리듬을 바꾼다.
- 장식용 카드·목업·큰 빈 영역은 사용하지 않는다. 여백은 섹션 구분, 페이지 호흡, 강조를 위해서만 남긴다.

## 7. 표·차트

- 정확한 값 조회는 표, 크기 비교는 0기준 막대, 시간 추세는 선을 우선 검토한다.
- 차트는 페이지 질문에 직접 답해야 한다. 단위·기간·분모·원자료 값 또는 출처를 함께 둔다.
- 당기 열, 합계, 의사결정에 중요한 위험 값만 강조한다.
- 기존 chart ID를 다른 질문에 확장하면 채택한 원리, 적용하지 않은 규칙, 열폭, 분할 정책을 결정 기록에 남긴다.
- 표와 차트를 중복 사용하려면 차트가 패턴을, 표가 정확한 값을 제공하는 등 서로 다른 역할이 있어야 한다.

## 8. 내용 초과·부족 처리

넘침은 다음 순서로 해결한다.

1. 불필요한 반복 문장 편집
2. 열 병합 또는 자료·해설 폭 조정
3. 표를 의미 단위로 분할하거나 다음 페이지로 이동
4. 페이지 추가
5. 정해진 범위 안에서 간격 미세 조정

본문·주석·표 글자를 최소값 아래로 줄이거나 `overflow:hidden`, 축소 transform, 내용 삭제로 감추지 않는다. 빈 공간은 내용을 덧붙여 채우기 전에 페이지 질문과 그룹 구조가 맞는지 먼저 검토한다.

## 9. 레퍼런스 적용 기록

레퍼런스마다 다음을 함께 기록한다.

- 문서·페이지·실제 관찰 내용
- 채택한 관계 또는 구성 원리
- 적용하지 않은 색·치수·서체·여백
- 한국어/판형에 맞게 바꾼 자체 값
- 적용 후 렌더·출력 검수 상태

원본에서 측정하지 않은 pt·열·거터를 원본 사양으로 쓰지 않는다. 미리보기 확보와 디자인 채택을 구분한다.

## 10. 합격 기준

- 내용 QC: 원장·산식·단위·기간·미제공값·판단 조건이 일치한다.
- 구조 QC: 페이지 질문과 제목·표·차트·해석·한계가 연결된다.
- 화면 QC: 제목·본문·표·주석이 잘리지 않고 페이지 리듬과 그룹핑이 보인다.
- PDF QC: 실제 A4 페이지 수, 폰트, 글리프, 표 분할, footer 겹침을 확인한다.
- 출력 QC: 100% 크기에서 본문·표·주석을 읽을 수 있고 흑백에서도 강조가 구분된다.
- 사용자 검토: 실제 기업 보고서다운지, 강조와 밀도가 적절한지 Bishop이 최종 선택한다.

자동 검사 통과는 디자인 승인이나 독자 이해 입증이 아니다.

## 다음 문서로의 확장

- 투자검토 IM: 거래 구조·가치평가·리스크·투자조건을 추가하고 가로 대조 지면을 별도 profile로 둔다.
- 기술제안서: 요구사항·아키텍처·구축 범위·검수·책임 경계를 추가한다.
- 산업분석: 시장 정의·가치사슬·추세·시나리오·근거 출처를 추가한다.

각 유형은 이 기업현황 profile을 그대로 복사하지 않고 독자 질문과 매체에 맞게 변형한다.
