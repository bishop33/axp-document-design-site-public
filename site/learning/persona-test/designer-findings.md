## 단계별 결정

1. 질문 고정: 이사회가 8명·연간 현금지출 6억원의 채용 확대를 바로 승인할 수 있는지 검토한다. 별도 표지는 두지 않았다. 기간·금액·가상 데이터 경고를 각 지면에서 확인할 수 있게 작성했다.
2. 원장 보존: 원장 값과 단순 산식만 썼다. 영업현금 감소 원인, 고객별 금액, 다음 해 추가매출·ROI는 만들지 않았다. ‘보류’는 제공 자료가 부족하다는 비전문가 검토 제안이며 전문 재무 판정으로 표시하지 않았다.
3. 전개 선택: 1쪽 3개년 실적, 2쪽 사업·분기·고객, 3쪽 현금 연결, 4쪽 보류 이유와 재상정 자료. 페이지마다 주장·근거·해석·한계를 작성했다.
4. 그리드 선택: 1·3쪽 financial-table, 2쪽 asymmetric-analysis, 4쪽 modular-evidence. 지면 바탕 6열은 공통이다. 2쪽은 4열 근거+2열 해설, 4쪽은 4+2 → 전폭 → 3+3으로 정보 관계에 맞춰 병합했다. 3+3 영역은 독립 주제이며 이어 읽는 대칭 2단 본문이라고 분류하지 않았다.
5. 차트 선택: 3개년은 table-values와 증감 문장으로 표현했다. 세 계열을 겹친 line보다 각 금액 조회를 우선했다. 사업별 금액은 0~60억원 bar, 현금은 부호·잔액/흐름을 구분한 table-values를 택했다. waterfall·pie는 검토 후 미사용했다. 재상정 표는 table-matrix 원칙을 확장한 자체 적용이며 제품 비교 원본을 그대로 복제한 것이 아니다.
6. 조판 보충: 가이드의 웹 px를 인쇄 pt로 단순 전환하지 않았다. A01~A11의 치수·서체·간격·흑백 선택은 개인 전문지식이다. catalog의 9행 고정 regions는 내용 흐름의 자동 높이로 바꿨다. 원본 grid를 수치까지 충실히 구현했다고 주장하지 않는다.
7. 검증 범위 제한: HTML 구조와 계산을 로컬에서 확인한다. 네트워크·브라우저·git·기존 제작 스크립트 실행은 하지 않았다. 실제 보고서의 시각 품질과 인쇄 4쪽 여부는 미검증으로 남긴다.

## 자체 보충값과 수용 기준

전체 값은 decisions.json의 assumedRules와 report.html CSS에 대응한다. A4 210×297mm, 좌우18mm, 상16mm, 하13mm, 본문9.5/14pt, 표9/13pt, 주석8.5/12pt를 택했다. 본문폭174mm를 6열과 5mm 거터로 나누므로 열폭은 약24.8333mm다. 4열 폭114.3333mm, 2열54.6667mm, 3열84.5mm다. 행 높이는 내용에 맡기고 섹션 간6mm, 소제목 뒤3mm, 문단 뒤3mm를 지정했다. 전역 baseline grid는 쓰지 않았다.

Pretendard는 font-family 첫 순위로 지정했으나 내장하지 않았다. 설치되지 않은 환경은 로컬 한글 서체로 fallback된다. 외부 요청 없이 문서 내용을 읽을 수 있게 했지만, 폰트 선택과 줄바꿈의 동일성은 보장하지 않는다. 보고서는 외부 JS·CSS·이미지·폰트를 불러오지 않는다. 2025 열의 연회색이 인쇄에서 빠져도 연도 헤더로 뜻을 읽을 수 있다.

수용은 단계별로 구분한다. 구조 수용에는 4개 article·A4 선언·선택 ID 실재·원장 보존·근거 인접·외부 로딩 없음이 필요하다. 출력 수용에는 실제 PDF가 A4 4쪽이고 제목·표·주석·꼬리말이 잘리거나 겹치지 않아야 한다. 디자인 수용에는 실제 크기에서 표 수치·주석이 읽히고 자료와 해설의 관계가 분명해야 한다. 최종 내용·디자인 채택은 Bishop 검토와 별도 QC가 필요하다. 구조 수용을 나머지 단계의 통과로 해석하지 않는다.

## 구체적 발견

### D-P1-01: 가이드만으로는 채용 승인에 필요한 내용 검증을 채울 수 없음

- 재현 근거: protocol의 역할별 비용·채용시점·추가매출·수주 확도 공백과 examples.json single의 회수 지연 서사를 대조한다. 예시의 서사를 복제하면 이번 원장에 없는 원인을 만들게 된다. 이는 가이드에 재무 답을 요구한다는 뜻이 아니라 원고 인계 경계를 명시해야 한다는 발견이다.
- 제작자 영향: 디자이너가 보기 좋은 결론형 제목을 쓰는 과정에서 원인을 단정하거나 ‘9−6=3’을 전망으로 오해할 수 있다.
- 이번 대응: 원인 미확인, 단순 잔여의 한계, 보류 제안을 원고에 명시했다. 새로운 재무 기준을 만들지 않았다.
- 보완안: 독자 판단·원장·허용 산식·미제공값·전문 검수 담당을 문서 제작 시작 조건으로 제공한다.
- 재테스트 통과조건: 같은 입력으로 다시 제작했을 때 미제공 원인·전망·고객별 금액을 만들지 않고, 3억원의 성격과 승인 공백을 정확히 표시한다. 별도 재무 검수자가 확인해야 한다.

### D-P1-02: 출력 검증을 할 수 없어 실제 4쪽과 넘침을 확정할 수 없음

- 재현 근거: topics.js pages는 최종 PDF의 서체·줄바꿈·표 분할 확인을 요구한다. 이번에는 사용자 지시로 브라우저/네트워크를 시도하지 않았다. CSS의 4개 A4 선언은 최종 출력 4쪽의 증거가 아니다.
- 제작자 영향: 폰트 fallback과 인쇄 엔진 차이로 4쪽의 긴 제목, 표 줄바꿈, 꼬리말 위치가 달라질 수 있다.
- 이번 대응: overflow:hidden·축소 transform·내용 잘라내기를 사용하지 않았다. 실제 렌더 여부를 false로 기록했다.
- 보완안: 허용된 환경에서 지정 폰트를 고정한 PDF와 100% 크기 지면을 별도 검수한다.
- 재테스트 통과조건: 실제 A4 4쪽, 모든 원고 보존, 수치·주석·꼬리말 겹침 및 잘림 없음, 한글 글리프 정상. 화면 검사와 인쇄 검사는 별도 기록한다.

### D-P2-01: 원칙에서 실제 조판 값으로 옮기는 단계에 디자이너의 보충이 필요함

- 재현 근거: topics.js type/space의 16px·20/28px, 32/8px는 통제 비교의 예시값이다. grid-systems.json은 자체 pt 사양·9행 regions를 제공하지만 긴 한글 제목·표 셀 내용 증가에 대한 조정 우선순위는 해당 항목에 없다.
- 제작자 영향: 값 복제 또는 고정 행 높이를 유지하면 자료와 해설 사이에 불필요한 공간이나 넘침이 생길 수 있다. 실제 발생을 렌더로 확인한 것은 아니다.
- 이번 대응: A01~A04, A10으로 값과 override를 명시했다. 개인 전문지식으로 해결한 부분을 가이드 성과로 돌리지 않았다.
- 보완안: 한글 실원고를 사용한 A4 제작 시트에 값의 적용 범위, 긴 제목·표 넘침 시 분할/폭 변경 우선순위를 제시한다.
- 재테스트 통과조건: 입력 분량이 늘어도 내용 삭제 없이 조정 이유·override를 기록하고, 별도 출력 검사에서 정상이어야 한다.

### D-P2-02: 공개 레퍼런스의 관찰은 선택 근거이며 재현 가능한 사양은 아님

- 재현 근거: NBIM 15·16쪽 PNG는 표·주석 관계를 보여주지만 한글 본문의 pt·행간·열폭을 정해주지 않는다. catalog도 작은 글자와 상단 여백 적용에 주의를 명시한다.
- 제작자 영향: 원본의 큰 상단 공백이나 강조색, 도넛 형태만 모방할 수 있다.
- 이번 대응: 관찰 가능한 정렬·인접·간격만 선택했고 수치 사양은 자체 가정으로 분리했다.
- 보완안: 원본 관찰 → 채택한 관계 → 자체 한국어 적용 → 적용하지 않은 조건을 묶어 제공한다.
- 재테스트 통과조건: 원본과 다른 매체·언어로 옮길 때 미측정 사양을 원본 사실로 쓰지 않고, 적용 결과를 별도 검수한다.

### D-P2-03: 독립 HTML의 서체 재현 조건이 확정되지 않음

- 재현 근거: type은 Pretendard를 기본으로 정한다. 이번 report.html은 font-family 지정만 하고 font 파일은 포함하지 않았다.
- 제작자 영향: 오프라인 읽기는 가능하나 환경별 줄바꿈과 높이가 달라질 수 있다.
- 이번 대응: 로컬 fallback을 지정하고 미검증 상태로 인계했다. 폰트가 실제 사용됐다고 말하지 않는다.
- 보완안: 사용 가능한 폰트 파일과 라이선스, 한국어 글리프 범위를 확인한 후 내장 또는 고정된 출력 환경을 정한다.
- 재테스트 통과조건: 네트워크가 없는 별도 환경에서 선택 폰트와 모든 글리프를 확인하고 동일 원고의 출력 페이지 수·줄바꿈을 대조한다.

## 검증 기록과 인계

Node의 fs/assert를 사용한 source-only 검사를 실행했고 통과했다. 선택한 grid/chart/reference ID의 원본 존재 및 HTML/decisions 대응, 4개 article의 제목·꼬리말·표, A4 치수 선언, 외부 resource 참조 0건을 확인했다. HTML의 연간·분기·현금 표에서 숫자를 읽어 원장과 대조했고, 구성·분기 합계120, 현금20+9−6−3+0=20, 고객 비중40%, 증감률20/25/−10%, 이익률10/12/12.5%, 채용비/전년 영업현금66.7%, 단순 잔여3의 전망 아님 표시를 확인했다. 막대의 60/42/18 값에 대응하는 100/70/30% 길이 선언도 일치했다. 이는 소스 검사 결과이며 HTML 렌더·실제 막대 길이 측정·넘침 검사·인쇄 4쪽 판정은 아니다.

통합 요청에 따라 각 article에 `data-page="1"`~`"4"`를 추가하고 순서를 확인했다. report.html에는 상대 resource 경로, 외부 JS/CSS/이미지/폰트 요청, runtime 의존이 없다. 그대로 `public/learning/persona-test/designer.html`에 복사해도 내부 참조를 수정할 필요가 없는 소스다. 실제 사이트 복사·UI 변경·게시·브라우저 실행은 하지 않았다. 로컬 서체 fallback에 따른 출력 차이 가능성은 남는다. 통합 담당은 이 파일을 원본 스냅샷으로 사용할 수 있으며 다른 persona를 기다리는 후속 작업은 없다.

최우선 인계 사항은 재무 입력 부족(D-P1-01), 출력 미검증(D-P1-02), 서체 미고정(D-P2-03)이다. 이 세 파일은 검토 가능한 실제 제작물이며 승인된 보고서 예시·가이드의 품질 입증·일반 사용자 실험 결과가 아니다.
