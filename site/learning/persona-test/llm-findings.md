# llm 페르소나 실제 제작 시험

2026-09-22. 명시된 규칙을 적용하는 문서 생성 에이전트의 단독 시뮬레이션입니다. 한국어 A4 세로 4쪽 원고를 실제 HTML로 작성했습니다. 보고서의 실적·기업은 전부 가상이며, 전문 내용 QC·디자인 QC·Bishop 채택 전입니다. 실제 사용자 실험이나 모델 간 비교가 아닙니다.

## 수행과 파일 소유권

- 완료: 제공 지침·가이드 읽기, 로컬 원본 이미지 1쪽 관찰, 보고서 4쪽 작성, 결정·가정 기록, source-only 검사.
- 수정 범위: 이 `llm` 폴더의 report.html, findings.md, decisions.json만. 공유 STATE.md·TEAM.md·사이트 UI·공개 폴더는 수정하지 않았습니다. 아래 인계 기록으로 공유 상태 갱신을 대신합니다.
- 네트워크·브라우저·git·기존 제작 스크립트 실행·게시 없음. 다른 persona를 기다리거나 읽지 않았습니다.
- TodoWrite 도구는 세션에 제공되지 않아 호출하지 못했습니다. 위 완료 목록을 작업 기록으로 남깁니다.
- `report.html`은 inline CSS와 HTML 텍스트만 사용합니다. script, 외부 CSS, 이미지, CDN, 상대 경로 의존이 없습니다. 변경 없이 `public/learning/persona-test/llm.html`에 복사 가능한 소스 구조이나 실제 복사·게시·해당 경로에서의 실행은 하지 않았습니다.
- 네 개 article은 각각 `data-page="1"`~`"4"`를 갖습니다. 실제 인쇄 페이지 수 4쪽을 검증했다는 뜻은 아닙니다.

## 단계별 실제 결정

1. 독자·질문 확정: 이사회가 8명 추가 채용을 바로 승인할 수 있는지 판단하도록 구성했습니다. 채용 시점·효과 미제공 때문에 작성자의 판단으로 보류를 제안했습니다. 사실과 권고를 구분했습니다.
2. 4쪽 분할: 실적과 판단 → 매출 구성·고객 집중 → 현금 → 재심의 조건. 모든 쪽에 주장·수치 또는 원장 공백·해석·한계를 작성했습니다. 표지 전용 페이지는 없습니다.
3. 표현 선택: 3개년 값은 `table-values`, 사업 구성은 `bar`, 현금은 부호 있는 조회표로 결정했습니다. 연간 매출 구성의 정확한 비중도 막대 옆에 적었습니다. 추세를 반드시 선으로 그려야 한다는 규칙은 만들지 않았습니다.
4. 그리드 적용: p1·p3은 `financial-table`, p2·p4는 `continuous-text`의 원리를 사용했습니다. 실제 CSS는 6열·10pt 거터이며 모든 블록을 전폭 병합합니다. 행 높이는 자연 흐름으로 선언했고, 9행 모듈이나 baseline 정합을 구현했다고 하지 않습니다.
5. 자체 보충: 본문 10/15pt, 좌우 여백 18mm, 섹션 사이 5mm 등의 token을 선언했습니다. 완전한 값은 decisions.json의 A01~A11 및 report.html CSS에 있습니다. 가이드의 원칙만으로 이 숫자가 확정됐다고 주장하지 않습니다.
6. 검증: 데이터 합계·산식, JSON, ID 존재, 4개 페이지, 외부 자산 참조 부재를 소스에서 확인했습니다. 실제 줄바꿈·넘침·인쇄 페이지 수는 남겨 두었습니다.

## 주요 발견

### F1 / P1 / 조판 token과 grid override 계약이 미완성

- 재현 근거: `grid-systems.json`의 continuous-text는 margin 62, financial-table은 38, 두 시스템은 rows 9와 고정 regions를 제안합니다. `examples.json` single의 본문은 8.5/12pt입니다. `topics.js` type은 실제 판형·폭·행간을 함께 결정하도록 설명하지만 이 작업용 통합 token과 우선순위는 주지 않습니다.
- 제작자 영향: 숫자를 기계적으로 조합하면 다른 페이지 체계가 섞입니다. 이번 결과에는 18mm 여백, 10/15pt 본문, 자연 행 흐름 등 자체 가정이 필요했습니다. 174mm 전폭 본문이 한국어 정독에 적합한지는 미확인입니다.
- 보완안: approved/proposed 상태를 가진 출력 profile과 margin·type·spacing·region override 계약을 제공하고, 각 페이지에 채택값을 직렬화합니다.
- 재테스트 통과조건: 같은 원고를 다른 생성 에이전트가 만들 때 모든 token의 근거·override가 추적되고, 미정 값을 자동 확정하지 않아야 합니다. 이어 실제 A4 렌더에서 읽기 폭·제목 결속·넘침을 별도 확인해야 합니다.

### F2 / P1 / 고정 4쪽과 overflow 처리의 출력 계약 부족

- 재현 근거: `topics.js` pages는 제목·표 분할·최종 PDF 점검을 요구하지만 overflow의 실패 조건과 재배치 절차는 지정하지 않습니다. 이번 report는 297mm 고정 높이 4개 article, `overflow:visible`입니다.
- 제작자 영향: DOM 페이지가 4개여도 실제 출력이 4쪽이라는 보장은 없습니다. 렌더 없이 통과시키면 글이 다음 페이지나 footer로 침범할 위험이 남습니다.
- 보완안: 자동 축소·숨김·내용 삭제를 금지한 상태로 overflow 시 재조판 요청을 반환하는 계약과 검수 항목을 추가합니다. 이번에는 원고를 그대로 보존하고 미검증으로 남겼습니다.
- 재테스트 통과조건: 접근 복구 후 실제 A4 출력이 정확히 4쪽이고, 모든 원고가 보이며, 본문·footer 겹침과 잘린 행이 없음을 모든 페이지에서 확인합니다. 이번에는 브라우저 재시도도 하지 않았습니다.

### F3 / P1 / 의사결정 근거의 공백은 디자인 가이드로 해결할 수 없음

- 재현 근거: protocol에 채용 시점·역할별 비용·추가매출·수주 확도 미제공이 명시돼 있습니다. single 예시는 여신 심사이며 이번 인력 승인과 판단 조건이 다릅니다.
- 제작자 영향: 원고 템플릿을 복제하면 회수 지연, 인력 효과, ROI를 꾸며낼 수 있습니다. 이번에는 미제공을 유지하고 보류·재심의 자료 요청을 전문 판단에 따른 제안으로 구분했습니다.
- 보완안: 원장 필드에 관측·계산·가정·미제공·제안 타입을 두고 재무 산식의 외삽 금지 조건을 함께 전달합니다.
- 재테스트 통과조건: 9−6=3을 전망·순현금으로 표시하지 않고, 구독60을 ARR로 바꾸지 않으며, 고객별 매출·채용 ROI를 생성하지 않아야 합니다. 추가 자료 없는 경우 승인 근거 부족을 문서 안에 남겨야 합니다.

### F4 / P2 / 오프라인 서체의 재현성 조건이 미정

- 재현 근거: 기본 가이드는 Pretendard를 지정합니다. 단일 HTML의 외부 의존 금지 아래 이번 파일은 local Pretendard와 시스템 fallback을 선언했습니다. 폰트 파일을 내장하지 않았습니다.
- 제작자 영향: 다른 장치로 복사하면 같은 글꼴·줄바꿈·행 높이를 보장할 수 없습니다. 파일은 독립적으로 열리는 구조이지만 조판의 동일성은 별도 문제입니다.
- 보완안: 배포 가능한 글꼴 내장 profile 또는 명시적 fallback 예외와 환경별 검수 절차를 마련합니다.
- 재테스트 통과조건: Pretendard 설치/미설치 환경에서 한글 누락·본문 침범이 없고, 선택된 글꼴을 검사 기록에 남겨야 합니다. 동일 조판을 요구하면 내장 서체로 다시 검증해야 합니다.

### F5 / P2 / 참고 이미지의 관찰과 실행 규칙 연결이 수동임

- 재현 근거: nbim-annual-2025는 실제 p15 이미지와 관찰을 제공하지만 당기 열 강조·주석 배치의 HTML token 매핑은 없습니다. p16의 관찰은 catalog 기록으로만 읽었습니다.
- 제작자 영향: 원본의 작은 글자·큰 상단 여백까지 복제하거나 미리보기 준비를 승인으로 오인할 수 있습니다. 이번에는 p15의 정렬·강조만 선택하고 색은 회색으로 바꿨습니다.
- 보완안: 참고 페이지마다 채택한 관계, 채택하지 않은 요소, 자체 값, 검증 상태를 연결합니다.
- 재테스트 통과조건: 사용 reference ID와 정확한 페이지, 채택·제외 요소가 결과물 결정 기록에서 일치하고 원본 수치를 자체 가독성 권장값으로 소개하지 않아야 합니다.

### F6 / P2 / 초안의 언어 일관성 오류 및 정정 기록

- 발견: decisions.json 최초 초안의 `limitations[0]`, `limitations[1]` 두 문장이 일본어였습니다. 한국어 산출물 요구를 위반한 실제 QA 결함입니다. 디자인·내용 개선으로 분류하지 않습니다.
- 영향: 핵심 한계 설명을 사용자가 요청한 언어로 읽을 수 없고, 통합 보고서에 그대로 포함될 위험이 있었습니다.
- 정정 이력: 페이지의 data-page 통합 변경을 반영하면서 두 문장을 한국어로 수정했습니다. 이후 총괄이 이 오류를 별도 QA 이력으로 보존하도록 지적하여 F6 기록과 decisions.json의 languageQAIssue를 추가했습니다. 초기 기록에서 이 언어 오류를 명시적으로 보고하지 않은 점도 남깁니다.
- 정정 후 문장 1: “공개 가이드의 로컬 소스를 직접 읽는 유리한 조건이며 일반 사용자의 UI 조작 시험이 아님”.
- 정정 후 문장 2: “A4 CSS 페이지 4개를 작성했으나 실제 출력 페이지 수와 넘침은 미검증”.
- 재테스트: report.html과 decisions.json에서 일본어 가나 문자가 없음을 소스 검사로 확인했습니다. 두 문장이 한국어이고 원래의 검증 한계를 유지하는지 직접 대조했습니다. 가나 부재 검사만으로 모든 언어·문체 품질이 입증되지는 않습니다.
- 수용 기준: 두 limitations가 한국어이며, 렌더 미검증·일반 사용자보다 유리한 조건이라는 한계를 빠뜨리지 않고, F6 이력이 통합 시 보존돼야 합니다.

## 독립 QC 응답 / Q3 수용

- 지적: 4쪽의 정성적 근거 요청표에 `table-values` ID를 사용했으나 adaptation 설명이 누락됐습니다. Q3를 수용합니다. 기존 ID가 유효하다는 정적 검사는 해당 표가 catalog 원형과 의미상 일치한다는 증거가 아니었습니다.
- 조치: decisions.json의 `chartAdaptations`에 4쪽의 목적, 채택한 조회 원리, 조건 인접 배치의 별도 근거, 적용하지 않는 수치 규칙을 기록했습니다. 숫자 우측 정렬·소수 자릿수 통일·수치 열 단위 및 합산 규칙은 문장 중심 표에 해당하지 않습니다. 문장 속 원장 수치와 단위는 유지합니다.
