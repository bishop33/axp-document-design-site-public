# 문서는 목적에서 시작해 검수를 거쳐 다시 개선으로 돌아옵니다

목적을 가진 독자에게 필요한 정보를 모으고, 검증하고, 읽기 쉬운 구조와 표현으로 바꿔 전달합니다. 단계마다 담당, 넘기는 산출물, 다음 단계로 넘어가는 기준이 정해져 있습니다.

- 상태: 검토 중
- 갱신: 2026-09-29
- 주소: https://bishop33.github.io/axp-document-design-site-public/docs/workflow/process/

문서 제작 흐름 (Mermaid 원고)

```mermaid

  s1["`**01 목적**

  s2["`**02 수집**
```

## 단계와 통과 기준

| 단계 | 담당 | 받는 것 | 내놓는 것 | 다음으로 넘기는 기준 |
|---|---|---|---|---|
| 01 목적 | 기획 | 요청, 독자, 사용 상황 | 문서 개요: 독자·결정할 일·답할 질문 3–7개 | 질문마다 “답이 무엇이면 결정이 달라지는지”가 적혀 있다 |
| 02 수집 | 리서치 | 문서 개요 | 자료 목록: 출처·기준일·확인 범위 | 질문마다 1차 출처가 하나 이상 있다 |
| 03 검증 | 검증 | 자료 목록, 수치 | 데이터 원장: 단위·기간·분모·산식, 확인·미확인 구분 | 같은 수치가 문서 전체에서 한 값이다 |
| 04 구조화 | 편집 | 원장, 질문 | 원고와 쪽 구성: 쪽마다 결론 한 문장 + 근거 | 결론 문장만 이어 읽어도 논리가 선다 |
| 05 표현 | 디자인 | 원고, 쪽 구성 | 지면: 그리드·표·차트·도식 | 쪽마다 표현이 [표현 고르기](/docs/basics/data/) 기준에 맞는다 |
| 06 검수 | 검수 | 지면, 원장 | 검수 기록: P0–P2 지적과 처리 | P0·P1이 남아 있지 않다 |
| 07 전달 | 기획 | 승인된 지면 | PDF·인쇄본·발표본, 변경 기록 | 독자가 받는 형식으로 확인했다 |
| 08 개선 | 전원 | 독자 반응, 검수 기록 | 규칙 수정안(이 가이드) | 반복된 지적이 규칙으로 바뀌었다 |

## 지킬 것

- 단계를 건너뛰지 않습니다. 검수(06)에서 나온 지적은 원인이 있는 단계로 되돌립니다. 표현 문제는 표현(05)으로, 내용 문제는 구조화(04)나 검증(03)으로 갑니다.
- 산출물은 다음 담당이 읽을 수 있는 파일로 넘깁니다. 말로 전한 조건은 원장이나 원고에 적습니다.
- 한 사람이 자신이 만든 산출물의 최종 검수자가 되지 않습니다.
- 정적 검사 통과는 디자인 승인이 아닙니다. 최종 디자인 판단은 Bishop이 합니다.
